# PR review corrections

Owner review on 2026-10-30 corrected two design omissions as well as implementation issues in the initial PR head
`b6d65fca`. The card now requires resume guidance for the session that was actually created and distinguishes an
observed unset effort parameter from absent evidence.

| Concern                           | Verified behavior and correction                                                                                                                                                                                                                                                                                                                                                      |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Hint target and presentation      | The hint ran after session creation. Repeating start, fork or fresh resume could collide or create another child. Guidance now resumes the actual session, with its Forge-root directory when necessary, using the standard command block. Incognito guidance offers a new nameless launch because cleanup deletes the old session. Long prompts and creation-only flags are omitted. |
| Extra launch probe                | The hint issued a second blocking runtime request. It now consumes the existing cost-baseline response through a transient parsed snapshot and an op event carrying the actual session being launched.                                                                                                                                                                                |
| Unset versus unknown              | A valid record with null applied value and null wire is rendered as `unset`; missing or unusable observations remain `unknown`. Changed requests can display `unset<-high` or `unset (stale)`.                                                                                                                                                                                        |
| Tier validation                   | An unknown requested string or malformed tier previously discarded every tier. Safe client-requested vocabulary is retained and rendered literally in the CLI, while malformed records are isolated and resolved/applied levels remain strict.                                                                                                                                        |
| Passthrough metadata and work     | An inactive configured floor appeared enforced, and untracked requests built discarded records. Only override mode reports its floor; requests without a valid launch ID skip observation-only catalog lookup and record construction.                                                                                                                                                |
| Reachable proxy fallback          | Invalid route fields discarded the reachable runtime and misreported `proxy_unavailable`. Route fallback and effort evidence now remain independent. Invalid backend IDs stay unknown. This requires malformed route metadata, not an ordinary healthy response.                                                                                                                      |
| Passthrough default               | Missing default tier now uses the passthrough handler's Sonnet fallback without inventing translated-route evidence.                                                                                                                                                                                                                                                                  |
| Client construction and callbacks | The builder now returns its final effort result where mutations occur. Production clients already accept `on_effort_applied`; affected test doubles were updated and callers pass it directly. No runtime failure was attributed to the previous conditional kwargs.                                                                                                                  |
| Dead helpers                      | The unused context-window derivation, tier helper and string-only resolver wrapper were removed after a caller audit. Context fallback regression coverage now exercises the actual rendered bar.                                                                                                                                                                                     |

The reachable-proxy regression reproduced all four cases before the fix: config/commitment route fallback, each with
valid effort or an older response without effort. The post-fix tests require observed effort or the accurate
`proxy_effort_unavailable` reason. Launch integration executes generated recovery commands for start, unnamed fork,
unnamed fresh resume, a child in another Forge root, and incognito recreation.

Final commands, results and full-log hashes are retained in [review-checks.json](review-checks.json). Full logs remain
temporary local diagnostics under `/tmp/forge-effective-effort-20261030/`.

The first review pre-commit run normalized an import in the hint test; after restaging, every hook passed.
