The 15 copied summaries preserve their original JSON values, including historical recommendations; repository formatting
may normalize their bytes. Provenance hashes describe the original local source files. Later results supersede earlier
pending decisions. The provenance record was generated by reading existing artifacts; no tests were rerun. Identity
verification retains multiplicity and reports counts, outcomes and normalized multiset hashes for 11 local
stability/serial JUnit reports, two integration reports and eight CI identity lists. Normalization is limited to the
three documented parameter-ID renames and GitHub's masking of one synthetic `user:pass@example.com` URL fixture. That
fixture value is test data, not a credential.

The clean integration set equals the baseline minus exactly 22 mapped removals, and its one wheel has the same SHA-256
as the three baseline builds. The disk-full attempt is invalid performance evidence. Cache warmth and image reuse
confound the full integration timing difference; only 21.211 seconds is directly attributed to removed baseline work.

The final CI summaries distinguish a failed job attempt from per-test retries: the first attempt passed both suites and
runtime health, then failed temporary-venv removal. A single job retry on the same commit passed cleanup. This does not
identify the writer or repair the possible teardown race. Runtime evidence here uses Python 3.13.11; the setup-python
step's 3.11.17 is not evidence of a Python 3.11 suite run.

Part B later repeated the cleanup failure at `5a30b345` after both suites and runtime health passed. Its retained
summary records the failed job without a retry; diagnosis belongs to the
[cleanup proposal](../../../proposed/wheel_runtime_cleanup_failure/card.md).
